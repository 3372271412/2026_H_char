## 4. 硬件与引脚总表

当前器件为 **TI MSPM0G3507，Cortex-M0+，LQFP-64(PM)**。

| 功能 | 外设/引脚 | 当前用途与备注 |
|---|---|---|
| 外部高速晶振 | PA5/PA6 | HFXT 40MHz，经 PLL 得到 80MHz MCLK |
| SWD | PA19/PA20 | SWDIO/SWCLK |
| LED | **PB22** | 心跳，低电平点亮；部分源码注释误写 PA22 |
| 菜单选择键 | PA18 | 内部下拉，高电平按下；主菜单循环 Task1～6 |
| 用户确认键 | PB21 | 内部上拉，低电平按下；进入任务、启动或确认 |
| OLED SDA/SCL | PA28/PA31 | SSD1306 0x3C，软件 I2C，不占硬件 I2C |
| 灰度地址 | PB0/PB1/PB10 | 74HC4051 AD0/AD1/AD2 |
| 灰度 ADC | PB25 / ADC0_CH4 | 8 路逐路选通采样 |
| TB6612 PWMA/PWMB | PA12/PA13 | TIMG0 CC0/CC1，40MHz/2000=20kHz |
| TB6612 方向 | PB17/PB19/PA16/PB24 | AIN1/AIN2/BIN1/BIN2；STBY 由硬件拉高 |
| 物理右轮编码器 | PA26/PA27 | TIMG8 硬件 QEI |
| 物理左轮编码器 | PA25/PA14 | GPIO 双边沿软件正交解码，GROUP1 IRQ |
| MaixCam | UART3，PB2 TX/PB3 RX | 115200 8N1；视觉数据与图传开关命令 |
| X42S 步进驱动 | UART1，PB6 TX/PB7 RX | 115200 8N1；电机地址 1 |
| 10ms 控制定时器 | TIMG12 | ZERO 中断通知 CONTROL 任务 |

### 4.1 编码器左右映射

硬件命名和物理轮位置曾发生变化，当前 `encoder_get_data()` 已在驱动内部统一语义：

```text
TIMG8 QEI(PA26/PA27) -> 物理右轮 -> 输出为 right_count/right_delta
GPIO(PA25/PA14)      -> 物理左轮 -> 输出为 left_count/left_delta
```

应用层不应再次交换左右轮。不同任务使用不同实测 CPR：

- 菜单 Task2 循线一圈：2500 counts/rev；
- Task4/5/6：1500 counts/rev。

### 4.2 MaixCam 协议

当前生产协议是 8 字节大端帧：

```text
0xFE + x(uint16) + vx(int32, px/s) + 0xFD
```

- `x=0xFFFF` 表示当前帧没有真实检测到钢球；
- 接收成功后记录 `frame_id` 和 MCU `tick_ms`；
- 图传命令：`5A 01 A5` 开启、`5A 02 A5` 关闭；
- 关闭图传只关闭网络图像流，MaixCam 仍通过 UART 发送球坐标；
- `docs/vision_integration_guide.md` 中的 15 字节 `x/y/w/h/score/count` 协议是历史版本，不适用于当前代码。

### 4.3 步进电机控制

管球使用 X42S/Emm V5 UART 协议：

- 地址：1；
- 位置速度：110RPM；
- 加速度：130；
- 使用 `0xFD` 完整位置模式，方向和绝对脉冲数分开发送；
- `raF=1`，按绝对位置模式工作；
- 启动前执行立即停止、解除堵转保护、使能和快速位置参数配置；
- 当前控制链不读取并校验每条位置命令的 ACK。

## 5. 系统启动、任务与同步

### 5.1 启动流程

```text
Reset_Handler
  -> C 运行库 __main
  -> main()
     -> SYSCFG_DL_init()
     -> led_init()
     -> key_init()
     -> app_tasks_start()
        -> maixcam_init()
        -> tb6612_init()
        -> encoder_init()
        -> gray_sensor_init()
        -> speed_service_init()
        -> line_tracking_service_init()
        -> 锁存车轮和步进电机急停
        -> 创建 5 个应用任务
        -> vTaskStartScheduler()
```

`main.c` 保持最小化，绝大多数硬件组件在 `app_tasks_start()` 中初始化。

### 5.2 FreeRTOS 任务

栈参数是 FreeRTOS 的 `StackType_t` 数量，在 Cortex-M0+ 上通常为 4 字节/项。

| 任务 | 优先级 | 栈 | 触发方式 | 职责 |
|---|---:|---:|---|---|
| `MAIXCAM` | 4 | 384 | UART3 字节队列阻塞 | 解析视觉帧并更新球快照 |
| `CONTROL` | 3 | 512 | TIMG12 10ms 通知 | 严格按当前 active 任务执行一个 10ms step |
| `KEY` | 2 | 256 | 10ms 轮询 | 双按键、菜单状态、完成检测、延时关闭图传 |
| `OLED` | 1 | 512 | 100ms 周期 | 菜单与任务状态显示 |
| `LED` | 1 | 128 | 500ms 周期 | 心跳灯 |

CONTROL 调度优先级顺序为：

```c
Task5/6 -> Task4 -> Task3 -> 菜单Task2对应的task1 -> 底层task2
```

理论上同一时刻只允许一个上层竞赛状态机 active。

### 5.3 任务间通信

| 对象 | 所属模块 | 形式 | 作用 |
|---|---|---|---|
| MaixCam RX | `maixcam.c` | 64 字节队列 | UART3 ISR 写字节，解析任务读 |
| `g_ball` | `maixcam.c` | 临界区保护快照 | 解析任务写，控制/OLED 读 |
| 速度目标 | `speed_service.c` | 长度 1 覆盖队列 | 上层只保留最新左右轮目标 |
| 速度状态 | `speed_service.c` | 长度 1 覆盖队列 | RPM、目标、累计计数、停止状态 |
| 循线命令 | `line_tracking_service.c` | 长度 1 覆盖队列 | START、START_CHECKPOINT、ABORT |
| 循线状态 | `line_tracking_service.c` | 长度 1 覆盖队列 | 灰度、位置、差速、距离、故障 |
| 控制节拍 | `app_tasks.c` | 任务通知 | TIMG12 ISR 唤醒 CONTROL |

当前没有互斥锁保护的共享总线：OLED 是独立 GPIO 软件 I2C，UART1 和 UART3 分属不同外设。

### 5.4 10ms 过载保护

CONTROL 每次执行：

```c
notify_count = ulTaskNotifyTake(pdTRUE, portMAX_DELAY);
if (notify_count != 1) {
    handle_control_overrun();
}
```

如果积压了两个或更多 10ms 通知，代码不会补跑过时周期，而是立即停车并将运行页面转为 FAULT。这是明确的安全设计，但也意味着单次控制路径若偶发超过约 20ms，会直接结束任务。

## 6. 核心数据流与控制架构

### 6.1 循线链路

```text
PB0/PB1/PB10 选择 74HC4051 通道
  -> PB25 ADC0_CH4，每路 8 次平均
  -> 逐路 black/white 标定归一化到 0~4095
  -> black_strength = 4095 - normalized
  -> 8 路加权位置（权重 -7,-5,-3,-1,1,3,5,7）
  -> 位置式 PD 产生 turn_rpm
  -> 丢线搜索 / 重捕平滑 / 弯道减速 / 轮速整形
  -> left=base-turn，right=base+turn
  -> speed_service
```

判线规则：

- 1～4 路强黑：正常黑线；
- 0 路：全白丢线；
- 5 路强黑：过宽黑区，按丢线处理；
- ≥6 路强黑：全黑检查点；
- 菜单 Task2 的上层终点检测额外采用 ≥4 路强黑首帧制动。

通用安全监督包括：ADC 失败、标定无效、速度状态不可用、1s 无编码进度、连续丢线 5s 和单次服务最长 120s。

### 6.2 双轮速度闭环

```text
每 10ms 读取编码器增量
  -> 累计 5 次形成 50ms 窗口
  -> rpm10 = delta * 600000 / (CPR * period_ms)
  -> 0.5 一阶低通
  -> 目标斜坡（每 50ms 最多 100RPM）
  -> 左右轮独立增量式 PID
  -> PWM 限幅 ±80
  -> TB6612 20kHz PWM
```

速度 PID 使用千倍整数参数：

```text
Δu[k] = Kp(e[k]-e[k-1]) + Ki*e[k] + Kd(e[k]-2e[k-1]+e[k-2])
u[k]  = clamp(u[k-1] + Δu[k])
```

目标同时为 0 时立即清零设定点、PWM 和 PID，并使用 TB6612 短接制动。

### 6.3 管球链路

```text
MaixCam x/vx
  -> 位置误差 target_x - ball_x
  -> 外环：desired_vel = kp_pos * error
  -> 内环：tilt = kp_vel * (desired_vel - filtered_ball_vel)
  -> 非对称倾角、球速自适应限幅、死区/有界启动脉冲
  -> Task4/5/6 车体运动前馈和弯道前馈
  -> 保持倾角查表
  -> X42S 绝对位置命令
```

基础管球参数：

| 参数 | 当前值 |
|---|---:|
| 中心 `g_t2_target_x` | 165px |
| `kp_pos / kp_vel` | 3000 / 1200（千倍整数） |

## 7. 六个菜单任务现状

### 7.1 菜单与通用交互

- PA18：仅在主菜单循环选择 Task1～Task6；
- PB21：从主菜单进入任务页，在任务页按各任务规则启动/确认；
- 当前没有从任务页返回菜单的操作，必须复位；
- Task2～Task6 完成或故障且图传关闭后，可用 PB21 重跑当前任务；
- 完成或故障后延时 1s 关闭图传；
- OLED 以秒显示任务时间，完成后冻结；
- Task4 从 READY 后车辆真正启动时计时，其余运动任务按各自启动时刻计时。

### 7.2 Task1：图传

状态逻辑完全位于 `app_tasks.c`：

1. 第一次 PB21：发送 `5A 01 A5`，开启图传并计时；
2. 第二次 PB21：任务完成，冻结时间；
3. 1s 后发送 `5A 02 A5` 关闭图传。

没有自动超时，也不启动小车或管球控制。

### 7.3 Task2：循线一圈

内部入口：`task2_lap_start/step/get_status`。

状态：

```text

```

关键参数：

| 循线 Kp/Ki/Kd | 6/0/25（存储值为实际值×1000） |
| 弯道速度 | 60%，上限100RPM |
| 速度环 Kp/Ki/Kd | 350/280/0 |
| 编码 CPR | 2500 |
| 启动终点屏蔽 | 500ms |
| 驶离起点确认 | 正常线连续50ms |

### 7.4 Task3：O→+5cm→-5cm

状态：

```text
IDLE -> GO_POS5 -> HOLD_POS5 -> GO_NEG5 -> COMPLETE
```

进入页面时只使能步进电机并调平，不开图传、不计时、不运行闭环。PB21 后才启动：

- +5cm：225px；
- -5cm：105px；
- +5cm 预制动基础裕量：5px；
- +5cm 到达后停留：0ms，立即折返；

- 底层使用 Task2 的 3000/1200、80px/s、+120/-80 脉冲参数。

Task3 没有独立的总超时或 FAULT 状态；视觉长期丢失时底层会进入 LOST，但上层页面可能一直保持 RUNNING。

## 8. 安全机制

当前软件安全策略较完整：

1. 启动时先锁存 `speed_service_emergency_stop()` 和 `ball_control_emergency_stop()`；
2. 速度 ESTOP 锁存后拒绝所有非零轮速目标，只有新任务显式清除；
3. 管球内核 `ball_control_*` 以及菜单Task3/4/5/6连续300ms无有效视觉会停车、报错或进入LOST；
4. 循线服务检测 ADC、标定、速度状态、编码进度、丢线和最长运行时间；
5. Task2 横线前沿同周期直接短接制动，不等待下一速度队列周期；
6. CONTROL 通知积压时不补跑旧周期，直接停车；
7. 任务创建失败、service 初始化失败、栈溢出都会锁存车轮和步进电机急停并死循环；
8. Task4/5/6 都有制动和停车后球保持确认；
9. ISR 只做编码器计数、UART 收字节或任务通知，不在 ISR 中运行控制算法。

尚未启用 `configUSE_MALLOC_FAILED_HOOK`，运行时动态内存失败没有应用钩子；任务和队列主要在启动阶段一次性创建。

## 14. 主要问题与维护风险

以下只记录，不在本次遍历中修改代码。

### 14.1 高优先级

1. **RAM 余量小**  
   32KB运行区已使用约30.23KB。新增任务、队列、日志缓冲和字库前必须测量heap与栈。

2. **10ms 控制路径余量有限**  
   灰度驱动按注释估算一次 8 路扫描约 6.4ms；管球每个新视觉帧还会在 CONTROL 任务中阻塞发送最多 13 个 UART1 字节。过载会直接触发整车故障停车。应以 GPIO 翻转或定时器测量真实最坏执行时间。

3. **Task3 无总超时/FAULT**  
   相机持续丢球或机构卡住时，Task3 可能永久停在 RUNNING，虽然底层会回水平或等待重现。

4. **步进电机命令不校验 ACK**  
   UART1 发送是阻塞的，但控制逻辑不确认驱动器是否执行成功；断线、堵转保护或地址错误不能被上层识别。

5. **Task6 允许范围大于标定范围**  
   允许 0..320px，固定保持表只有 105..225px；极端目标只沿用端点倾角，不能视为已完整标定的“任意位置”。

### 14.2 中优先级

6. **MaixCam 队列溢出没有计数**  
   `xQueueSendFromISR()` 返回值未检查，64 字节队列满时会静默丢字节。历史日志已观察到 UART 行断裂和突发冲刷，虽然那是 UART0 调试链路，但说明增加协议错误计数很有价值。

7. **`maixcam_init()` 不检查队列创建结果**  
   速度/循线 service 会检查队列，MaixCam 初始化没有等价失败返回。

8. **文档和注释代差较大**  
   `main.c`、`app_tasks.h`、LED 注释、`distance_control.h` CPR 说明、`line_tracking_config.h` 的 60s/120s 注释等存在陈旧信息。

9. **步进库 API 大小写不一致**  
   头文件声明 `Emm_V5_Modify_OM_ma()`，实现为 `Emm_V5_Modify_OM_mA()`；当前未调用，所以不影响构建，但未来调用会链接失败。

10. **通用 `util_abs_i32()` 没处理 `INT32_MIN`**  
    当前正常传感器数据不太可能触发，但它不是严格安全的通用绝对值实现。

11. **OLED 有重复全屏刷新**  
    `oled_task` 每轮先 `OLED_Clear()`，该函数已经刷新一次，绘制后又 `OLED_Refresh()`；每 100ms 周期实际发生两次全屏传输，增加低优先级 CPU 占用。

12. **任务页不能退出**  
    这是最新文档明确的阶段性设计，不是隐藏 bug，但现场误选任务后只能复位。

### 14.3 工程与资料风险

13. Keil/SDK/SysConfig 菜单和 VSCode 配置存在多套旧绝对路径；
14. `mspm0g3507_trm.pdf` 实际是 L 系列 32MHz TRM；
15. 仓库没有 CI、主机单元测试或一键命令行构建；
16. MaixCam 端当前 `main.py` 不在本仓库，MCU 与摄像头协议无法在单仓库内完整复现；
17. `keil/Objects/` 同时留有旧目标和新目标产物，分享时容易误取 HEX；
18. 现有 Task4 CSV 的串口行完整性较差，后续自动统计必须先做断行修复和版本识别。

## 16. 最终评价

该工程已经完成从通用 MSPM0 FreeRTOS 模板到竞赛整车控制系统的快速演进，当前最有价值的设计点是：

- 任务状态机、循线纯算法、速度纯算法和 RTOS/硬件 service 已形成较清晰的层次；
- 不同赛题任务使用独立的循线/速度 profile，避免调 Task5 时破坏 Task4；
- 视觉、循线和速度链路均通过快照或长度 1 队列传递最新状态；
- 对控制周期积压、视觉丢失、循线故障、任务创建失败和栈溢出都有停车策略；
- Task4/5/6 将启动、弯道、减速和制动前馈与反馈控制结合，符合实车调试中观察到的惯性问题；
- Git 分支保留了大量调参历史，生产分支则清理了 UART0 命令和遥测代码。

当前主要短板不是“功能缺失”，而是**文档代差、RAM/时序余量、当前菜单版本的重复性数据不足，以及 Task6 全范围标定不足**。在不继续大改架构的前提下，优先完成测时、测栈、连续实车复测和资料归档，收益高于继续增加新功能。
