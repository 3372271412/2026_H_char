# 工程分享与环境配置手册

本文说明：当你把本工程压缩发给别人后，对方如何配置环境，使工程可以在 Keil 中编译，并可以打开/运行 SysConfig GUI。

## 1. 对方需要安装的软件

请先安装以下软件：

1. Keil MDK-ARM
2. TI MSPM0 SDK，建议版本：`2.10.00.04`
3. TI SysConfig，建议版本：`1.26.2`
4. MSPM0 Keil Device Family Pack

> 注意：MSPM0 SDK 和 SysConfig 的安装路径不要求和本机一致。

## 2. 解压工程

将压缩包解压到任意目录，例如：

```text
D:\project\H_BallCar_Task1_6
```

路径中尽量不要包含中文和特殊字符。

## 3. 运行一键配置脚本

在工程根目录双击运行：

```text
setup_mspm0_env.bat
```

脚本会自动完成：

1. 设置用户环境变量：
   - `MSPM0_SDK`
   - `SYSCONFIG`
2. 按本机 MSPM0 SDK 路径修补 Keil 工程 `.uvprojx` 中的 include/lib 路径
3. 运行一次 SysConfig 生成验证

如果脚本没有自动找到安装路径，会提示输入：

```text
Input MSPM0 SDK path
Input SysConfig install path
```

示例：

```text
C:\ti\mspm0_sdk_2_10_00_04
C:\ti\sysconfig_1.26.2
```

或者：

```text
D:\tool\CCS\mspm0_sdk_2_10_00_04
D:\tool\CCS\sysconfig_desktop
```

脚本成功时会看到类似输出：

```text
[1/4] User environment variables are set:
[2/4] uvprojx paths patched.
[3/4] SysConfig menu config regenerated.
[4/4] Running SysConfig generation test...
Generating Code (main.syscfg)...
Setup done.
```

## 4. 重启 Keil

脚本使用 `setx`/用户环境变量方式保存路径。已经打开的 Keil 不会自动读取新的环境变量。

请执行：

1. 关闭 Keil
2. 重新打开 Keil 工程

## 5. 打开 Keil 工程并配置

打开：

```text
keil\H_BallCar_Task1_6.uvprojx
```

**必须勾选以下选项**（否则无法烧录）：

- **Options for Target → Target** → 勾选 **Use MicroLIB**
- **Options for Target → C/C++** → 勾选 **One ELF Section per Function**

然后直接 Build。

工程已配置 Before Make 自动运行：

```text
keil\syscfg.bat
```

因此每次编译前都会根据 `main.syscfg` 重新生成：

```text
ti_msp_dl_config.c
ti_msp_dl_config.h
Event.dot
```

## 6. 打开 SysConfig GUI

### 方法 A：使用 Keil Tools 菜单

如果 Keil Tools 菜单中没有 SysConfig 项，可以导入：

```text
keil\MSPM0_SDK_syscfg_menu_import.cfg
```

导入后通过 Tools 菜单打开 SysConfig GUI。脚本已自动将配置中的路径写入为绝对路径，无需手动修改。

### 方法 B：直接打开 main.syscfg

也可以用 SysConfig 软件直接打开：

```text
main.syscfg
```

保存后重新在 Keil 中 Build，工程会自动重新生成代码。

## 7. 环境变量说明

脚本会设置用户环境变量：

```text
MSPM0_SDK=<MSPM0 SDK 安装路径>
SYSCONFIG=<SysConfig 安装路径>
```

例如：

```text
MSPM0_SDK=C:\ti\mspm0_sdk_2_10_00_04
SYSCONFIG=C:\ti\sysconfig_1.26.2
```

## 8. 为什么脚本还要修补 .uvprojx？

Keil uVision 命令行对 include/lib 路径中的系统环境变量展开并不稳定。实际测试中，直接在 `.uvprojx` 中写：

```text
%MSPM0_SDK%\source
```

或：

```text
$(MSPM0_SDK)\source
```

可能导致 UV4 编译时找不到：

```text
ti/devices/msp/msp.h
```

因此本工程采用折中方案：

- SysConfig 脚本使用环境变量，便于移植
- Keil `.uvprojx` 编译 include/lib 路径由 `setup_mspm0_env.bat` 自动修补为本机实际绝对路径

这样对方只需要运行一次脚本，之后 Keil 编译即可正常工作。

## 9. 常见问题

### 9.1 找不到 `ti/devices/msp/msp.h`

原因：Keil 工程中的 SDK include 路径不正确。

解决：重新运行 `setup_mspm0_env.bat`，确认 SDK 路径正确。

### 9.2 烧录报 `Flash Download failed - Cortex-M0+`

原因：未勾选 MicroLIB 或芯片状态异常。

解决：
1. 检查 MicroLIB + One ELF Section 是否勾选
2. 拔 USB → 等 5 秒 → 重插 → Rebuild → Load
3. 如果还不行，先用 CCS/UniFlash 做一次 Mass Erase，再切回 Keil

### 9.3 SysConfig GUI 能打开，但文件没更新

原因：没有指定输出目录，或没有重新生成。

解决：

1. 确认已经使用本工程的 `keil\MSPM0_SDK_syscfg_menu_import.cfg`
2. 或直接 Build，Before Make 会自动运行 `keil\syscfg.bat`

### 9.4 修改环境变量后仍报错

原因：Keil 已经打开，未读取新的环境变量。

解决：关闭后重新打开 Keil。

### 9.5 脚本提示找不到 SysConfig node

确认 SysConfig 路径下存在：

```text
nodejs\node.exe
dist\cli.js
sysconfig_gui.bat
```

如果没有，说明输入的不是 SysConfig 安装目录。

## 10. 分享工程前检查清单

打包前建议确认以下文件存在：

```text
setup_mspm0_env.bat
scripts\setup_mspm0_env.ps1
keil\syscfg.bat
keil\MSPM0_SDK_syscfg_menu_import.cfg
keil\H_BallCar_Task1_6.uvprojx
main.syscfg
```

并建议先运行一次：

```text
setup_mspm0_env.bat
```

确认 SysConfig 生成通过、Keil 编译通过后再压缩分享。
