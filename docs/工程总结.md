# H_BallCar_Task1_6 工程总结

## 1. 工程概述

本工程是基于 **TI MSPM0G3507** 的 FreeRTOS 小车控制工程，使用 **Keil uVision + SysConfig + DriverLib** 开发。

当前工程已经从基础模板扩展为：

- LED 心跳任务
- UART0 启动信息与基础发送接口
- SSD1306 OLED 显示
- MPU6050 DMP 姿态角读取，并在复位后等待 yaw 稳定
- TB6612 双路直流电机驱动
- 双路增量编码器测速
- FreeRTOS 多任务、队列、任务通知
- 10ms 定时器统一节拍
- 50ms 双轮速度闭环，增量式 PID
- 50ms yaw 角闭环，位置式 PID 输出差速目标
- PB21 按键循环切换 yaw 目标角：`0° -> 45° -> 90° -> 135° -> 180° -> 0°`
- 对外接口可设置基准速度与目标 yaw 角

整体职责划分：

```text
main.c
  └─ 硬件初始化 + 启动 app_tasks_start()

Component/task/app_tasks.c
  └─ FreeRTOS 任务创建、ISR 分发与对外 API 转发

Component/service/*.c
  ├─ attitude_service：姿态稳定检测、yaw 零点归一与姿态快照逻辑
  └─ yaw_loop_service：yaw 目标/状态队列与串级 step 逻辑

Component/control/yaw_control.c
  └─ yaw 角环纯算法、目标斜坡、到位锁存、重捕获滞回

Component/control/speed_loop_core.c
  └─ 速度环纯算法：滤波、斜坡、PID、低速前馈、PWM 计算

Component/service/speed_service.c
  └─ 速度环适配层：FreeRTOS 队列、编码器读取、TB6612 输出、状态快照

Component/pid/pid.c
  ├─ 整数增量式 PID：双轮速度环
  └─ 整数位置式 PID：yaw 角度环
```

## 2. 当前硬件连接

### 2.1 LED 与按键

| 功能 | 引脚 | 说明 |
|---|---|---|
| LED | PB22 | 心跳指示灯 |
| KEY_USER | PB21 | 用户按键，内部上拉，按下低电平；当前用于 yaw 目标角 +45° 切换 |

> 旧版速度档位按键逻辑已经不再是当前主流程。当前 PB21 控制 yaw 目标角，速度基准由 `app_tasks_set_yaw_target()` 的 `base_speed_rpm` 参数决定，默认 `0 RPM`。

### 2.2 UART0

| 功能 | 引脚 | 说明 |
|---|---|---|
| UART0_TX | PA10 | 115200 8N1 |
| UART0_RX | PA11 | 115200 8N1，RX 中断入队 |

UART0 当前生产版主要用于启动信息、`printf`/`write` 重定向和基础调试发送。yaw 在线调参命令、`TEL` 遥测、自动调参脚本已经从生产版清理，保留在 `yaw-pid-debug-tuning` 分支历史中。

### 2.3 MPU6050

| 功能 | 引脚 | 说明 |
|---|---|---|
| SDA | PA0 | 硬件 I2C0 SDA |
| SCL | PA1 | 硬件 I2C0 SCL |
| INT | PB4 | DMP 数据就绪中断，下降沿触发 |

MPU6050 DMP yaw 在复位后存在慢漂稳定过程。当前 `attitude_task` 需要等待 pitch/roll/yaw 在稳定窗口内满足阈值后，才发布 `app_attitude_t` 姿态快照。实测从复位到 yaw 可用约 **20s** 左右。

### 2.4 OLED SSD1306

| 功能 | 引脚 | 说明 |
|---|---|---|
| SDA | PA28 | 软件 I2C SDA |
| SCL | PA31 | 软件 I2C SCL |

当前固定方案：

```text
MPU6050 使用硬件 I2C0：PA0/PA1
OLED 使用软件 I2C：PA28/PA31
```

原因是 PA0/PA1 与 PA28/PA31 都属于 I2C0 的可复用引脚组合，不能同时作为两条独立硬件 I2C 总线使用。

### 2.5 TB6612 电机驱动

| 功能 | 引脚 | 说明 |
|---|---|---|
| PWMA | PA12 | PWM_TB6612 CC0 |
| PWMB | PA13 | PWM_TB6612 CC1 |
| AIN1 | PB17 | 电机 A 方向控制 |
| AIN2 | PB19 | 电机 A 方向控制 |
| BIN1 | PA16 | 电机 B 方向控制 |
| BIN2 | PB24 | 电机 B 方向控制 |
| STBY | +5V | 硬件拉高使能 |

实测接线注意：

```text
TB6612 电机 A -> 物理右轮
TB6612 电机 B -> 物理左轮
```

因此速度闭环输出时使用：

```c
tb6612_set_speed(right_pwm, left_pwm);
```

### 2.6 编码器

| 功能 | 引脚 | 说明 |
|---|---|---|
| QEI A | PA26 | TIMG8 QEI 通道 A |
| QEI B | PA27 | TIMG8 QEI 通道 B |
| GPIO A | PA25 | GPIO 双边沿软件解码 |
| GPIO B | PA14 | GPIO 双边沿软件解码 |

`encoder_get_data()` 内部已经处理硬件通道与物理左右轮映射，应用层直接使用 `left_delta/right_delta` 即可。

编码器参数：

```c
#define ENCODER_COUNTS_PER_REV 440
```

## 4. 工程结构

```text
main.c
Component/
  led/
    led.c/h
    key.c/h
  UART/
    uart0.c/h
  oled/
    oled.c/h
  mpu6050/
    mpu6050.c/h
    mspm0_i2c.c/h
    inv_mpu*.c/h
  tb6612/
    tb6612.c/h
  encoder/
    encoder.c/h
  pid/
    pid.c/h
  common/
    util.h
  control/
    yaw_control.c/h
    speed_loop_core.c/h
  service/
    attitude_service.c/h
    yaw_loop_service.c/h
    speed_service.c/h
  task/
    app_tasks.c/h
main.syscfg
ti_msp_dl_config.c/h
FreeRTOSConfig.h
keil/
```

核心文件说明：

- `main.c`
  - 调用 `SYSCFG_DL_init()`
  - 初始化 LED、按键、UART、TB6612、编码器、MPU INT
  - 输出启动信息
  - 调用 `app_tasks_start()` 启动调度器

- `Component/task/app_tasks.c`
  - 集中保存 LED/MPU/YAW_LOOP/SPD_LOOP/YAW_KEY/OLED 任务入口
  - `yaw_loop_task` 是 yaw/speed 的胶水层：调用 `yaw_loop_service_step_10ms()`，当其返回 true（50ms 控制周期完成）时，读 yaw 状态快照做差速换算（left=base-turn, right=base+turn），再调用 `speed_service_set_target_with_ff()` 下发速度环；姿态失效时安全停车 `set_target(0,0)`
  - 控制/姿态任务入口只做等待/延时/调用 service step；按键与 OLED 任务逻辑保留在本文件便于频繁修改
  - 实现 GROUP1 与 TIMER_0 中断分发
  - 保留对外 API 转发：轮速目标、yaw 目标、等待 yaw 到位、应用状态快照

- `Component/service/attitude_service.c`
  - 姿态稳定窗口检测、yaw 零点归一与姿态快照发布
  - 不直接调用 MPU6050 驱动；`attitude_task` 调用 `Read_Quad(&att)` 读取姿态结构体后传入 pitch/roll/yaw

- `Component/service/yaw_loop_service.c`
  - yaw 目标队列、状态队列与串级 step 逻辑
  - 只做 yaw 环计算，将 `base_speed_rpm / turn_rpm / speed_ff_enable / attitude_valid` 写入状态快照
  - **不再直接调用 speed_service**：差速换算与速度环下发交由 `app_tasks.c` 胶水层的 `yaw_loop_task` 完成
  - 从而 yaw/speed 两个闭环可独立使用、调试或替换执行机构

- `Component/control/yaw_control.c`
  - 保存 yaw 可调参数
  - 实现 yaw 位置环、目标斜坡、动态限幅、到位锁存与重捕获滞回
  - 输出 `turn_rpm` 和速度低速前馈开关

- `Component/control/speed_loop_core.c`
  - 速度环纯算法核心：编码器增量累计、RPM 估算、滤波、目标斜坡、PID、低速前馈和 PWM 计算
  - 不直接依赖 FreeRTOS、编码器驱动或 TB6612，便于移植/单元测试

- `Component/service/speed_service.c`
  - 速度环适配层：管理速度目标/状态队列，读取 `encoder_get_data()`，调用 `speed_loop_core_update()`，输出到 `tb6612`
  - 对外公开目标设置与速度状态快照

- `Component/pid/pid.c`
  - `pid_inc_t`：整数增量式 PID，速度环使用。支持 reset、set_gain、输出限幅
  - `pid_pos_t`：整数位置式 PID，yaw 角环使用。核心 API：
    - `pid_pos_compute_error()`：常规闭环（内部自管积分）
    - `pid_pos_compute_with_integral()`：接受外部积分项，只做 P + D + 限幅 + 状态维护，供 yaw 等策略层自行管理积分分离/衰减
    - `pid_pos_get/set_integral_milli()`：积分项 getter/setter
    - `pid_pos_get_derr_start()`：处理 first_run 并返回误差变化，供策略层提前做 approaching 判断
  - `pid.c` 不包含任何控制策略（死区/积分分离/动态限幅/制动逻辑），这些属于 `yaw_control.c`

## 5. FreeRTOS 任务架构

当前主要任务：

| 任务 | 优先级 | 栈 | 触发源 | 功能 |
|---|---:|---:|---|---|
| `LED` | 1 | 128 | 500ms 周期 | 心跳灯 |
| `MPU` | 2 | 512 | MPU6050 INT 任务通知 | DMP 姿态读取；稳定后发布姿态 |
| `YAW_LOOP` | 4 | 384 | TIMER_0 10ms 任务通知 | 每 50ms 更新 yaw PID，先下发左右轮目标，再通知速度环 |
| `SPD_LOOP` | 3 | 512 | `YAW_LOOP` 任务通知 | 10ms 编码器采样 + 50ms 速度 PID |
| `YAW_KEY` | 2 | 192 | 10ms 轮询 | PB21 每按一次目标 yaw +45° |
| `OLED` | 1 | 512 | 姿态队列 peek + 200ms 周期 | 显示 yaw 目标、当前 yaw、误差、基准速度、turn 输出 |

生产版已删除 UART 在线调参任务和 TEL 遥测任务。

### 5.1 队列与环路解耦

当前队列按 service/control 拆分，`app_tasks.c` 不再持有业务队列：

```c
// attitude_service.c 内部私有
static QueueHandle_t g_attitude_queue;

// yaw_loop_service.c 内部私有
static QueueHandle_t g_yaw_target_queue;
static QueueHandle_t g_yaw_state_queue;

// speed_service.c 内部私有
static QueueHandle_t g_speed_target_queue;
static QueueHandle_t g_speed_state_queue;
```

用途：

| 队列 | 所属模块 | 生产者 | 消费者 | 内容 |
|---|---|---|---|---|
| `g_attitude_queue` | attitude_service | `attitude_task` | yaw loop / OLED / getter | MPU6050 稳定后的 `app_attitude_t` |
| `g_yaw_target_queue` | yaw_loop_service | 按键 / `app_tasks_set_yaw_target()` | `yaw_loop_task` | yaw 命令：基准速度、目标角、使能、reset |
| `g_yaw_state_queue` | yaw_loop_service | `yaw_loop_task` | OLED / wait/getter | `app_yaw_status_t` |
| `g_speed_target_queue` | speed_service | 速度 API / yaw 环 | `speed_loop_task` | 左右轮目标速度 + 低速前馈开关 |
| `g_speed_state_queue` | speed_service | `speed_loop_task` | wait/getter | 左右轮实测/目标速度、停止状态 |

这些队列句柄都保持模块私有。外部只通过 app/service getter 与 setter 访问，不直接接触队列句柄或 PID/PWM 运行状态。

### 5.2 外部速度目标接口

`Component/task/app_tasks.h` 暴露：

```c
bool app_tasks_set_wheel_speed_target(int32_t left_rpm, int32_t right_rpm);
```

用途：

```c
// 直行
app_tasks_set_wheel_speed_target(200, 200);

// 差速转向
app_tasks_set_wheel_speed_target(-100, 100);

// 停止
app_tasks_set_wheel_speed_target(0, 0);
```

普通外部调用不启用 yaw 专用低速前馈。yaw 环内部需要低速前馈时，通过 `speed_service_set_target_with_ff()` 下发目标，该函数不作为应用层公开 API。

### 5.3 yaw 闭环目标接口

`Component/task/app_tasks.h` 暴露：

```c
bool app_tasks_set_yaw_target(int32_t base_speed_rpm,
                              int32_t target_yaw_deg10);
```

参数含义：

```text
base_speed_rpm     基准速度，默认 0，可实现原地定向
目标 yaw 角 × 10   45° = 450，90° = 900
```

示例：

```c
// 原地闭环到 90°
app_tasks_set_yaw_target(0, 900);

// 以 80RPM 基准速度行驶，同时保持 45° 航向
app_tasks_set_yaw_target(80, 450);
```

### 5.4 yaw 到位等待接口

```c
int app_tasks_wait_yaw_settled(uint32_t timeout_ms);
```

返回规则：

- `0`：yaw 已进入到位/保持区且速度环已停止，或等待超时结束。
- `1`：未到位且仍在等待中；通常用于 `timeout_ms == 0` 的非阻塞轮询。

该接口内部组合 `yaw_loop_service_is_settled()` 与 `speed_service_wheels_stopped_snapshot()`，不要求速度环写 yaw 状态。

### 5.5 应用状态快照接口

`Component/task/app_tasks.h` 额外暴露只读 getter：

```c
bool app_tasks_get_attitude(app_attitude_t *out);
bool app_tasks_get_wheel_speed(app_wheel_speed_t *out);
bool app_tasks_get_yaw_status(app_yaw_status_t *out);
bool app_tasks_get_vehicle_state(app_vehicle_state_t *out);
```

这些结构体只包含应用层需要的角度、左右轮实测/目标速度、yaw 目标与到位状态；不暴露 PID 内部状态、PWM 输出、滤波累计值或队列句柄。

## 6. 控制链路

### 6.1 总体串级链路

当前由 `TIMER_0` 10ms 中断统一驱动：

```text
TIMER_0 10ms 中断
        ↓
vTaskNotifyGiveFromISR(g_yaw_loop_task_handle)
        ↓
yaw_loop_task 被唤醒
        ├─ 每 50ms：计算 yaw PID，将 base/turn/前馈/姿态状态写入快照
        ├─ 胶水层读 yaw 快照 → 差速换算（left = base - turn, right = base + turn）
        ├─ 胶水层调用 speed_service_set_target_with_ff() 下发速度环
        └─ 每 10ms：通知 speed_loop_task
        ↓
speed_loop_task 被唤醒
        ├─ 每 10ms：读取编码器增量
        └─ 每 50ms：计算 RPM、速度 PID、更新 PWM
```

这样保证上层 yaw 目标先更新，下层速度环再执行，避免时序错位。

### 6.2 速度闭环链路

```text
speed_loop_task 10ms 唤醒
        ↓
speed_service_step_10ms()
        ├─ 内部读取最新左右轮目标
        ├─ encoder_get_data() 读取编码器增量
        ├─ 累计 5 次，即 50ms 窗口
        ├─ encoder_delta_to_rpm10() 换算速度
        ├─ 一阶低通滤波
        ├─ 速度目标斜坡 setpoint
        ├─ 左右轮独立增量式 PID
        ├─ 低速启动前馈（由目标消息中的开关决定）
        └─ tb6612_set_speed(right_pwm, left_pwm)
        ↓
内部发布 speed_service_state_t 快照
```

速度目标/状态队列封装在 `speed_service.c` 内；速度算法核心封装在 `speed_loop_core.c` 内，便于后续循线、遥控等上层功能单独使用速度环，也便于移植到其它硬件适配层。

### 6.3 yaw 闭环链路

```text
MPU6050 DMP yaw（稳定后发布）
        ↓
yaw_loop_service_step_10ms() 每 50ms 读取姿态快照
        ↓
yaw_control_update()
        ├─ 目标斜坡
        ├─ 位置式 PID（P+D+clamp 委托 pid_pos_compute_with_integral）
        ├─ 积分分离/衰减（yaw 自行管理，通过 pid_pos_get/set_integral_milli 读写）
        ├─ 动态限幅 + 接近制动 + 静态补偿
        ├─ 到位锁存 + 重捕获滞回
        └─ 输出 turn_rpm、speed_ff_enable、attitude_valid → 写入状态快照
        ↓
yaw_loop_task（app_tasks 胶水层）
        ├─ 姿态失效 → speed_service_set_target(0, 0)  安全停车
        ├─ 正常 → 差速换算
        │     left_target  = base_speed_rpm - turn_rpm
        │     right_target = base_speed_rpm + turn_rpm
        └─ speed_service_set_target_with_ff(left, right, speed_ff_enable)
```

> yaw_loop_service 本身不依赖 speed_service，差速换算与下发由 app_tasks 胶水层完成。
> 因此 yaw 环和速度环可独立使能/禁用/调试，也可替换为不同的执行机构。
> 若实测发现 yaw 越修越偏，应交换 `left/right` 中 `turn_rpm` 的正负号。当前实测方向正确。

### 6.4 控制周期

```c
#define ENCODER_SPEED_PERIOD_MS 10
#define YAW_LOOP_TIMER_TICK_MS  10
#define YAW_LOOP_PERIOD_MS      50
```

速度计算与 PID 更新周期：

```text
5 × 10ms = 50ms
```

选择 50ms 的原因：

- 低速下 10ms 编码器计数太少，速度量化误差明显。
- 50ms 累积窗口可以获得更稳定的 RPM 估计。
- 对当前直流减速电机速度环和 yaw 角环响应较合适。

### 6.5 RPM 计算

```c
rpm10 = delta * 600000 / (ENCODER_COUNTS_PER_REV * period_ms)
```

其中：

```text
600000 = 60s/min × 1000ms/s × 10
```

内部使用 `int64_t` 防止乘法溢出。

### 6.6 速度滤波

当前一阶低通滤波：

```c
filtered += (raw - filtered) / 2;
```

也就是：

```text
filtered_new = 0.5 × raw + 0.5 × filtered_old
```

用于降低编码器量化噪声和瞬时跳变。

### 6.7 速度目标斜坡

当前目标速度斜坡：

```c
#define SPEED_RAMP_STEP_RPM 100
```

每个 50ms 控制周期，内部 setpoint 最多变化 100 RPM。

该值是在 yaw 闭环调试后从旧版 30 RPM 提高而来。原因是 yaw 上层环需要更快改变左右轮目标，旧值会明显拖慢角度响应。

## 7. PID 控制器

### 7.1 速度环默认参数

```c
#define PID_DEFAULT_KP_MILLI 80   // Kp = 0.080
#define PID_DEFAULT_KI_MILLI 50   // Ki = 0.050
#define PID_DEFAULT_KD_MILLI 0    // Kd = 0
#define PID_OUTPUT_MIN      (-80)
#define PID_OUTPUT_MAX      (80)
```

调试结果：

- 低速 60/80 RPM 基本无稳态误差。
- 反向阶跃超调较小。
- D 项关闭，避免放大编码器速度量化噪声。

### 7.2 速度环增量式 PID 公式

```text
Δu[k] = Kp × (e[k] - e[k-1])
      + Ki × e[k]
      + Kd × (e[k] - 2e[k-1] + e[k-2])

u[k] = clamp(u[k-1] + Δu[k], out_min, out_max)
```

误差：

```text
e[k] = target - measured
```

### 7.3 yaw 角环默认参数

当前 yaw 角环参数集中在 `Component/control/yaw_control.c` 顶部：

```c
#define YAW_PID_DEFAULT_KP_MILLI       120
#define YAW_PID_DEFAULT_KI_MILLI       0
#define YAW_PID_DEFAULT_KD_MILLI       170
#define YAW_PID_OUTPUT_LIMIT_RPM       200
#define YAW_DYNAMIC_CAP_BASE_RPM       18
#define YAW_DYNAMIC_CAP_ERR_DIV        14
#define YAW_MIN_TURN_RPM               7
#define YAW_DEADBAND_DEG10             12   // 1.2° 内认为到位
#define YAW_REACQUIRE_DEG10            25   // 到位后超过 2.5° 才重新修正
#define YAW_REACQUIRE_CONFIRM_COUNT    2U
#define YAW_INTEGRAL_ZONE_DEG10        120
#define YAW_INTEGRAL_LIMIT_RPM         0
#define YAW_MIN_TURN_ZONE_DEG10        180
#define YAW_TARGET_RAMP_STEP_DEG10     150  // 15°/50ms
#define YAW_RECOVER_MAX_TURN_RPM       15
#define YAW_APPROACH_BRAKE_ZONE_DEG10  120
#define YAW_APPROACH_DERR_DEG10        2
```

当前策略：

- yaw 层不再依赖积分追尾差，`Ki=0`、积分限幅为 0，避免扰动回正后积分残留导致超调。
- 死区外给明确的小修正，避免低于静摩擦的小碎步。
- 接近目标且误差快速变小时直接清零，由速度环短接制动，减少扰动回正后冲过头。
- 进入到位区后锁存；只有误差连续超过重捕获阈值才重新修正，过滤 MPU 小噪声和机械回弹。

### 7.4 速度低速前馈参数

速度低速前馈参数集中在 `Component/control/speed_loop_core.c` 顶部：

```c
#define SPEED_START_FF_PWM               18
#define SPEED_START_FF_SETPOINT_RPM      90
#define SPEED_START_FF_ERR_RPM           2
#define SPEED_START_FF_MIN_SETPOINT_RPM  4
#define SPEED_START_FF_FULL_SETPOINT_RPM 24
#define SPEED_START_FF_MIN_PWM           12
```

前馈开关不再使用全局变量，而是随速度目标消息传入速度环。普通 `app_tasks_set_wheel_speed_target()` 默认关闭前馈；yaw 环根据 `yaw_control_update()` 输出决定是否启用。

### 7.5 yaw 调试结论

当前效果：

- 阶跃响应已满足当前需求。
- 扰动回正已明显改善，偶发小抖动通过到位锁存和重捕获确认抑制。
- 相比继续增大 Ki，当前选择“允许小静差，换取低超调和无小碎步”。

### 7.5 整数实现

PID 参数使用千倍整数：

```text
kp_milli = Kp × 1000
ki_milli = Ki × 1000
kd_milli = Kd × 1000
```

速度环内部使用：

```c
int32_t output_milli;
```

保留输出小数累计，避免整数截断导致低速控制不连续。

### 7.6 已修正的限幅逻辑

当前 `pid_inc_compute()` 使用：

```c
next_milli = output_milli + delta_milli;
output_milli = clamp(next_milli, min_milli, max_milli);
```

不再采用“超过限幅就把本次增量清零”的做法。这样输出可以正常到达 `out_min/out_max`，不会在接近限幅时提前削弱响应。

## 9. MPU6050 与中断流程

### 9.1 数据流

```text
MPU6050 DMP 数据就绪
        ↓
PB4 下降沿
        ↓
GROUP1_IRQHandler()
        ↓
vTaskNotifyGiveFromISR(g_attitude_task_handle)
        ↓
attitude_task 唤醒
        ↓
Read_Quad(&att)
        ↓
读取 att.pitch/roll/yaw 传入稳定窗口检测
        ↓
稳定后写入 g_attitude_queue
```

### 9.2 上电稳定策略

当前 `attitude_task` 上电后不会立即发布姿态，而是等待 pitch/roll/yaw 在稳定窗口内满足阈值后才写入姿态队列。

关键参数：

```c
#define MPU_STABLE_REQUIRED_SAMPLES    80U
#define MPU_STABLE_PITCH_RANGE_DEG     1.50f
#define MPU_STABLE_ROLL_RANGE_DEG      1.50f
#define MPU_STABLE_YAW_RANGE_DEG       1.00f
```

实测 yaw 复位稳定约需 20s 左右。在此之前：

- `g_attitude_queue` 可能没有有效数据。
- `yaw_loop_task` 读不到有效姿态时会 reset yaw PID，并下发 `0,0` 轮速目标。
- OLED 显示 `MPU stabilizing / wait about 20s`。

### 9.3 ISR 原则

ISR 中只做：

- 判断中断来源
- 清中断标志
- 通知对应任务

不在 ISR 中做 I2C 访问。

原因：

- I2C 读写可能等待或超时。
- ISR 中阻塞会破坏实时性。
- FreeRTOS 下外设访问应放在任务上下文。

### 9.4 GROUP1 中断复用

`GROUP1_IRQHandler()` 当前分发两个来源：

1. 右轮编码器 GPIO 双边沿中断
2. MPU6050 INT 数据就绪中断

处理顺序：

```text
encoder_right_int_is_pending()
  -> encoder_right_irq_handler()

MPU6050_IntIsPending()
  -> MPU6050_IntClear()
  -> vTaskNotifyGiveFromISR(g_attitude_task_handle)
```

## 10. OLED 显示

OLED 使用 PA28/PA31 软件 I2C。

当前主要显示 yaw 闭环状态：

```text
第 0 行：YT: 目标 yaw 角 + ON/OFF
第 1 行：YN: 当前 yaw 角
第 2 行：YE: yaw 误差
第 3 行：B: 基准速度  T: yaw PID 输出 turn_rpm
```

如果 MPU 还未稳定并发布姿态，则显示：

```text
MPU stabilizing
wait about 20s
YT:...
yaw not ready
```

刷新周期约 `200ms`。

注意：OLED 软件 I2C 刷屏耗时较长，因此 OLED 任务优先级保持较低，避免影响控制任务。

## 12. 已遇到的问题与结论

### 12.1 OLED 与 MPU6050 的 I2C 冲突

问题：

```text
OLED    -> PA28/PA31
MPU6050 -> PA0/PA1
```

两组引脚都是 I2C0 的复用方案，不能同时作为两路独立硬件 I2C。

结论：

```text
MPU6050 使用硬件 I2C0
OLED 使用软件 I2C
```

### 12.2 ISR 不能直接读 MPU6050

`Read_Quad()`（现已改为 `Read_Quad(mpu_attitude_t*)`）涉及 I2C 访问，不能放在 GPIO ISR 中。

当前方案：

```text
ISR 只通知任务，attitude_task 中调用 attitude_service 读取 I2C
```

### 12.3 MPU yaw 稳定时间较长

问题：复位后 yaw 角会慢漂，约 20s 后才适合作为相对 0°。

当前方案：

- `attitude_task` 使用稳定窗口检测。
- 稳定前不发布有效姿态到 `g_attitude_queue`。
- `yaw_loop_task` 没有有效姿态时不输出转向，保持安全。
- OLED 显示等待提示。

### 12.4 编码器测速量化噪声

低速时 10ms 窗口内脉冲数少，RPM 抖动明显。

当前方案：

- 10ms 读取编码器增量
- 50ms 累计窗口计算 RPM
- 一阶低通滤波
- D 项默认关闭

### 12.5 正反转/差速切换冲击

原始阶跃目标容易在正反转或差速切换时产生冲击。

当前方案：

- 目标速度通过 `SPEED_RAMP_STEP_RPM = 100` 斜坡过渡
- 普通换档不一律 reset 速度 PID
- 目标为 0 时才立即停止并 reset

### 12.6 PID 输出限幅

原先如果“下一步输出超过限幅就清零本次增量”，可能导致输出到不了限幅边界。

当前方案：

```text
先累加，再 clamp
```

这样输出响应更自然。

### 12.7 yaw 静态误差与抗干扰

问题：纯 PD 或过小输出在地面静摩擦下容易出现静态误差；强干扰后恢复慢。

当前方案：

- `YAW_MIN_TURN_RPM = 7`，死区外给明确修正，避免小碎步。
- `Ki = 0`，保持态不靠积分追尾差，减少扰动回正后的积分残留。
- `YAW_DEADBAND_DEG10 = 12`，进入 1.2° 内认为到位。
- `YAW_REACQUIRE_DEG10 = 25` + 连续 2 次确认，到位后超过 2.5° 才重新修正。
- 接近目标且误差快速变小时清零 yaw 输出，速度环短接制动，减少超调。

调试结论：

- 继续增大 Ki 虽可减小静差，但容易增加扰动后的超调和尾部小碎步。
- 当前策略是允许小静差，优先换取低超调、低抖动和快速回稳。
- 单目标长时间 hold + 人工扰动比单纯阶跃更能暴露抗扰问题。

## 15. 结论

当前工程已经形成较完整的：

```text
MSPM0G3507 + FreeRTOS + MPU6050 DMP + OLED + TB6612 + 编码器 + 速度闭环 + yaw 角闭环
```

核心架构特点：

- 外设配置遵循 SysConfig
- `main.c` 只负责硬件初始化和启动调度器
- 任务间通过队列/任务通知松耦合通信
- MPU6050 I2C 读取放在任务中，不放在 ISR 中
- MPU yaw 稳定后才发布给控制环
- 10ms Timer 先通知 yaw 上层环，再由 yaw 环通知速度环
- 速度环由 50ms 增量式 PID 控制
- yaw 环由 50ms 位置式 PID 控制，并加入死区、积分分离、积分限幅、最小转向前馈
- PB21 可快速切换 0/45/90/135/180° 目标角
- 串口调试代码已从生产版清理，调试历史保留在 Git 分支中
